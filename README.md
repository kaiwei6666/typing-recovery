# Typing Recovery

修復忘記切換注音輸入法時打出的英文鍵位。目前完成英文鍵位轉注音、音節解析、離線字詞候選與排序、保守的誤打偵測提示、Tab 接受首選、混合文字局部修復、相鄰中文語境排序及本頁選字記憶。尚未做完整語意理解。

## 在 Chrome 使用

1. 開啟 `chrome://extensions/`，啟用開發人員模式。
2. 載入未封裝項目，選擇包含 `manifest.json` 的專案資料夾。
3. 開啟 `https://www.google.com/` 或 `https://www.google.com.tw/`。
4. 在搜尋框輸入 `su3cl3`，游標留在末端，停約半秒會出現「將『su3cl3』修復為『你好』？」提示。按 Tab 或點「套用（Tab）」直接接受，也可點「查看候選」逐字調整。
5. 沒有提示時，仍可對原始鍵位按 `Ctrl+Shift+U` 手動查看候選，也可以把「你」改選為「妳」。
6. 若只想轉注音，按 `Ctrl+Shift+Y`，結果為 `ㄋㄧˇㄏㄠˇ`。

兩個快捷鍵是不同入口，不需要先按 Y 再按 U；候選查詢需要原始英文鍵位。有反白時只處理選取範圍；沒有反白時，U 優先處理最後一段符合偵測條件的文字，找不到才開啟整個輸入框的候選；Y 仍轉換整個輸入框。候選視窗按 Esc 或「取消」不會改動原文。

更新程式後，需重新載入擴充功能並重新整理 Google 頁面。Chrome 新分頁不在支援範圍內。支援可編輯的 textarea 與 text/search/url/tel input；密碼、唯讀、停用及不支援文字選取的欄位不處理，輸入法組字中也不觸發。

## Phase 9：本頁選字記憶

- 在候選視窗實際套用的完整選字組合，會在**目前頁面**暫時記住；同一組注音再次開啟候選時，已套用的選擇排在前面，套用次數較多者優先。
- 例如第一次將 `cl3g4` 從預設「好事」改成「好市」並套用，本頁再次對 `cl3g4` 按 `Ctrl+Shift+U`，首選會是「好市」，並標示「本頁已套用 1 次」。
- 只記錄標準化注音讀音、所選漢字與本頁次數，不保留完整輸入框、前後文或網站資料。最多記住 100 組讀音，每組五種選擇。
- 記憶只存在該頁面的 content script 記憶體；重新整理、關閉頁籤或重新載入擴充功能就會清除。不使用 `chrome.storage`、Cookie 或網站儲存空間，不新增權限。
- 自動提示仍使用原本的詞庫、語境與保守門檻，不靠本頁記憶新增提示。點「查看候選」後才套用本頁排序，讓使用者再次確認。
- 選到字典外文字、音節不完整或只保留原始鍵位時不會記憶，避免建立無法重現的候選。

## Phase 8：相鄰中文語境排序

- 候選可參考修復範圍左右**緊鄰的一個中文字**。例如在 `cl3g4場` 中反白 `cl3g4` 後按 `Ctrl+Shift+U`，首選會由原本的「好事」調整為「好市」，套用後成為「好市場」。
- 空白、標點、Emoji 或其他字元會中斷語境，不跨界猜測。沒有相鄰中文字時，候選順序與 Phase 4 相同。
- 語境資料由既有離線詞庫的相鄰漢字統計產生，只保留出現至少五次的組合。分數為 `0.35 × log(count + 1)` 的排序加分，是可調整的啟發式，不是意圖機率。
- 語境只重排候選，不放寬 Phase 5 的自動偵測門檻。例如原本因候選接近而略過的 `cl3g4`，即使旁邊有「場」也不會自動提示；使用者可反白後手動開啟候選。
- 候選視窗會標示實際採用的「相鄰文字」，使用者仍須確認預覽後才替換。既有網址、Email、路徑保護與過期輸入檢查維持不變。
- 全部計算在本機完成，不記錄前後文、不連線，也不新增網站權限。

核心 API：

```js
const recovery = TypingRecovery.getCandidateRecovery("cl3g4");
TypingRecovery.rankCandidates(recovery)[0].text;                  // "好事"
TypingRecovery.rankCandidates(recovery, { right: "場" })[0].text; // "好市"
```

## Phase 7：混合文字的局部修復

- 例如 `我想用 Google 查 su3cl3 的意思`，提示只修復 `su3cl3`；按 Tab 後成為 `我想用 Google 查 你好 的意思`。周圍文字保留。
- `src/core/range-detector.js` 提供 `findRecoveryRanges(value)`，回傳原文、UTF-16 起訖位置、建議與偵測證據。中文、Emoji 等字元可分隔區段；不從連續英文單字或識別名稱內截取片段。
- 網址、Email、路徑及反引號程式碼採保守排除；仍不是完整的程式語言或自然語言辨識器。每一段均須通過 Phase 5 的詞彙及分數門檻。
- 若較大的重疊區段會降低詞彙覆蓋率，優先保留證據較完整的小區段。例如 `npm i su3cl3` 只修復 `su3cl3`，不會吞掉英文 `i`。
- 未受保護 token 末端的半形句點、逗號、分號、問號、冒號及驚嘆號視為句讀並保留。例如 `su3cl3. 下一句` 只修復句點前的鍵位；網址與 Email 仍維持整體排除。
- 多段符合時一次先處理最後一段；提示、查看候選與沒有反白的 U 快捷鍵使用相同範圍。有反白時以使用者選取為準。
- 自動提示仍要求游標在整個欄位末端；套用後游標停在被替換區段的末端。整個欄位任何文字變動都會讓既有提示失效，避免覆蓋新的內容。
- 一聲仍需要半形空白鍵；必要時區段包含最後一個一聲空白，套用時沿用既有規則移除。例如 `查 w96j0 的天氣` → `查 台灣的天氣`。想保留空白可開啟候選並勾選「保留原始空白」。
- 每個欄位最多 2,000 個 UTF-16 字元、128 個 ASCII token；單次合併最多八個以單一空白分隔的 token。最多八段結果與 512 個探測視窗，超出欄位／總量限制則不提示，請反白手動修復。
- 所有處理仍在本機，沒有新增權限或輸入紀錄。

## Phase 6：Tab 接受首選

- 自動提示可見且仍對應目前文字時，按不含修飾鍵的 Tab 會套用提示中的首選；也可點「套用（Tab）」。提示出現本身不會改字。
- 必須聚焦原輸入框、沒有反白，且游標位於文字末端。移動游標或反白時會隱藏提示；也可自行反白後用 `Ctrl+Shift+U` 指定範圍。
- 替換後焦點留在原輸入框，游標停在結果末端，並發出一次 `input` 事件。提示消失後，再按 Tab 會正常切換焦點。
- 沒有提示、提示尚未出現、文字已變動或欄位不可編輯時，Tab 不會被修復功能攔截。
- Shift+Tab、Ctrl/Alt/Meta+Tab、重複按鍵、輸入法組字事件及已被網頁取消的按鍵事件不會接受候選。
- Esc／「忽略」保留原文；「查看候選」仍可更換首選。Enter 維持網頁原本行為，不自動接受或攔截搜尋。

Phase 7 起提示會標明要替換的區段，僅修改該範圍。接受前請查看建議，偵測器與排序器不保證判斷正確。

## Phase 5：保守誤打偵測與提示

`src/core/detector.js` 提供 `TypingRecovery.detectRecovery(raw)`；`src/auto-hint.js` 在輸入暫停 450 ms 後呼叫偵測器。自動提示只針對目前聚焦且可編輯的 textarea、text/search input，僅在 manifest 原有的兩個 Google 網域執行。

- 單一待判斷區段最多 160 個 UTF-16 字元、2–32 個音節；每個音節都必須完整且有單字候選。
- 必須含至少一個明示聲調鍵 `3/4/6/7` 與英文字母；純數字、沒有聲調訊號的英文不提示。
- 大寫字母、網址／Email／程式路徑等特徵、原有中文與其他不支援字元會略過。這是字元與音節啟發式，不是完整英文辨識器。
- 首選必須有至少兩個字的詞彙證據，且詞彙覆蓋音節至少 60%；前兩名分數差必須至少 `log(1.5)`。沒有第二名時只檢查其他門檻。此差值不是可信機率。
- 提示不搶焦點，出現時不改原文；「查看候選」開啟現有確認視窗。從 Phase 6 起可按 Tab 明確接受首選，規則見上節。
- Esc 或「忽略」會關閉提示；每個欄位只在頁面記憶體保留最近一次忽略的文字，以避免相同內容重複提示。從提示開啟候選後，即使取消也不立刻重複提示。重新整理頁面會清除這個狀態。
- 繼續輸入、移開焦點、輸入法開始組字或開啟手動候選時會隱藏提示；內容已變動時不能套用過期提示。
- 自動偵測不處理 URL/tel input，但既有手動快捷鍵仍支援。密碼欄位不讀取候選。

例如 `su3cl3`、`g4ru,4`、`5j/ jp6` 會提示；`hello world`、`gpt4`、`1234567`、網址及 Email 不提示。單字 `su3`、候選接近的 `cl3g4`、大寫 `SU3CL3` 或未打完的文字可能刻意不提示，仍可用手動快捷鍵修復。合法型號或代碼也可能剛好符合注音鍵位，因此不保證零誤判。

### 偵測評估

```sh
node scripts/evaluate-detector.cjs
```

`tests/fixtures/detector-cases.json` 是 **54 個手工編寫的回歸案例，不是真實使用者語料或獨立驗證集**。目前結果：37 個正常案例未誤報，17 個誤打案例中提示 10 個、略過 7 個（召回率約 58.8%）。7 個略過案例也是保守策略的驗收項目；不能把「所有策略測試通過」當成偵測率 100%。這是底層單一區段偵測器的評估，不包含 Phase 7 的混合文字掃描；這些數字僅描述此小型案例集，不能推估實際準確率。

偵測與候選都在本機執行，不傳送輸入、不持久儲存輸入歷史，也沒有新增權限。

## Phase 4：詞彙候選與初步排序

`Ctrl+Shift+U` 現在會在逐字選單上方顯示最多五個「建議組合」，並以第一個建議填入預覽。點選建議會同步更新各字選單；也可手動改字、保留原文，或點「恢復逐字預設」回到 Phase 3 的字典順序。所有結果仍需按「套用替換」才會寫入輸入框。

| 原始鍵位 | 首選建議 |
| --- | --- |
| `su3cl3g4ru,4` | 你好世界 |
| `g4ru,4` | 世界 |
| `dl3g4` | 考試 |
| `cl3g4` | 好事 |
| `w961o3g45/4zj3` | 台北市政府 |
| `5j/ jp6` | 中文 |

這讓同樣的 `g4`（ㄕˋ）能在已收錄詞語中對應「世」「試」「事」「市」，不再只取單字表第一個字。仍有可能選錯，請確認預覽。

### 排序方式與範圍

- 離線詞庫包含 103,980 筆詞彙／讀音對應，長度為 2–6 個字，搭配單字與詞彙出現次數。來源、雜湊值與 MIT／libtabe 授權聲明見 [字典來源](third_party/mcbopomofo/README.md)。
- `src/core/ranker.js` 用動態規劃比較不同斷詞及字詞組合，每個位置保留最多五種不同輸出。單字可作為詞庫缺漏時的後備。
- 每個字詞的分數為 `log((count + 1) / total) + (字數 - 1) × log(3)`。`total` 是保留詞彙和單字去重後的加一平滑總數；後項是固定的詞內連續性加分。它是可調整的排序啟發式，不是使用者意圖的可信機率。
- 一般空白、標點、Emoji、原有中文、未收錄或未完成的音節會阻止跨界組詞；只允許跨過已辨識的一聲空白鍵。勾選「保留原始空白」仍會保留顯示中的空白。
- Phase 4 的基礎排序只使用選取範圍內的鍵位音節與詞庫；Phase 8 可讀取緊鄰中文字，Phase 9 可套用本頁暫存的已選組合。三者都不使用 AI 或網路。
- 尚不推測省略的聲調、不改寫 Phase 2 的音節切分；專有名詞、低頻詞或詞庫外用語可能需要逐字修改。一般英文仍可能被當成鍵位解析，請只對想修復的文字手動觸發。
- 詞庫約 4.8 MB，另有約 0.7 MB 的相鄰漢字統計，隨 content script 載入；排序最多處理 120 個音節。

核心 API：

```js
const recovery = TypingRecovery.getCandidateRecovery("g4ru,4");
const suggestions = TypingRecovery.rankCandidates(recovery);
// suggestions[0].text === "世界"
// suggestions[0].choices: ["世", "界"]
// suggestions[0].phrases: ["世界"]
// 依原有 composeCandidates() 套用選擇並保留非鍵位字元。
```

## Phase 3：離線中文字候選

新增 `src/core/dictionary.js`、`src/core/candidates.js` 及 `src/candidate-panel.js`，由 manifest 依序載入。

- 字典採用小麥注音單字表的 Big5 漢字子集：1,343 種帶聲調讀音、14,324 筆字候選。來源版本、篩選方式與 MIT 授權保存在 [third_party/mcbopomofo](third_party/mcbopomofo/README.md)。不涵蓋所有罕用字與異體字。
- 依確切聲調查詢，候選依原始字典順序排列；不宣稱第一個候選就是語境中正確的字。
- 查不到候選、音節不完整、缺聲調或孤立聲調都保留原始鍵位。字典缺少某個讀音不代表該讀音必定非法。
- 每個音節都可改選候選或「保留原文」，確認預覽後才替換。
- 一聲必須有半形空白。例如 `5j/ jp6` 可選成「中文」；預設移除已轉換音節的一聲空白鍵。可勾選「保留原始空白」得到「中 文」。多餘空白及其他字元保留。
- 候選視窗一次最多處理 120 個音節；更長輸入請反白分段處理。開啟後若輸入框內容被改動，會拒絕覆蓋並提示重新開啟。
- 字典隨擴充功能載入，查詢不連線、不儲存輸入歷史，不新增網站權限。

核心 API 範例（需先載入 parser、dictionary、candidates）：

```js
const recovery = TypingRecovery.getCandidateRecovery("su3cl3");
// recovery.units[0].candidates 包含「你」「妳」等候選。
TypingRecovery.composeCandidates(recovery, ["妳", "好"]); // "妳好"
TypingRecovery.composeCandidates(recovery, ["", "好"]);   // "su3好"
```

可測試：`su3cl3` → 你好、`5j/ jp6` → 中文、`a87` → 嗎，以及反白部分文字後選字。

## Phase 2：音節解析

依序載入 `src/core/keymap.js` 與 `src/core/syllable-parser.js` 後，可呼叫：

```js
const result = TypingRecovery.parseKeystrokes("su3cl3");
// result.raw: "su3cl3"
// result.zhuyin: "ㄋㄧˇㄏㄠˇ"
// result.syllables.map(s => s.zhuyin): ["ㄋㄧˇ", "ㄏㄠˇ"]
```

解析結果只存在函式回傳值中，不會記錄輸入歷史或傳送至伺服器。頁面的 `recoverCurrentInput()` 也會回傳解析結果。

| 欄位 | 意義 |
| --- | --- |
| `raw` | 原始文字，保留大小寫 |
| `zhuyin` | 鍵位映射後文字，保留空白與未映射字元 |
| `syllables` | 依聲母、介音、韻母順序切分出的暫定音節 |
| `segments` | 所有音節、原樣保留字元及無所屬聲調，依輸入順序排列 |
| `start` / `end` | 原始字串 UTF-16 範圍，end 不含在範圍內 |
| `tone` | 1–5；無法確認時為 `null` |
| `boundary` | `tone`、`space`、`structure`、`literal` 或 `end` |
| `issues` | `missing-tone`、`incomplete-body` 或 `orphan-tone` 等待處理情況 |

第一版規則：

- `6`、`3`、`4`、`7` 分別為二、三、四、輕聲，結束前面的音節。輕聲沿用鍵位輸入順序，顯示在音節後方。
- 半形空白可結束前面的音節並標記一聲；空白仍是獨立 segment，不會從輸出移除。
- 聲母／介音／韻母順序倒退或重複時，切出暫定邊界；未明示的聲調維持未知，不自行補成一聲。
- 不完整的聲母、缺少聲調、孤立聲調都保留並標記。`ㄓㄔㄕㄖㄗㄘㄙ` 可獨立構成音節主體。
- 大寫英文字母可映射，但 `raw` 保留原始大小寫；其他未映射字元原樣保留。

這是**結構解析器**，不是完整合法讀音驗證器。`issues: []` 不保證讀音合法，也不保證使用者原本想打中文；例如一般英文仍會照鍵位映射。缺少聲調與空白時的切分可能有歧義，後續需由合法音節表、字典與候選排序處理。

## 驗證

不需安裝套件，使用 Node.js 22 或以上執行：

```sh
node --test tests/recovery.test.cjs
```

涵蓋音節邊界、聲調、不完整輸入、Unicode、原文重建、字典查詢、詞彙完整性、同音字排序、不同斷詞比較、候選組合、偵測策略案例及使用模擬輸入框的快捷鍵整合。

```sh
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/browser_smoke.py
```

這會在全新的無頭 Chromium 設定檔載入真正的擴充功能，將 Google 網址攔截為本機測試頁，驗證詞彙建議、逐字覆寫及重設、取消、局部替換、游標、空白、過期輸入保護、自動提示、Tab／點擊接受、反白與修飾鍵保護、忽略、組字事件與窄視窗。它不使用你的 Chrome 設定檔，也不依賴 Google 現行版面；Google 真實搜尋框與系統輸入法仍需手動驗收。

## GitHub 自動測試

[Tests 工作流程](https://github.com/kaiwei6666/typing-recovery/actions/workflows/tests.yml) 在推送到 main、提出或更新以 main 為目標的 PR 時自動執行，也可從 Actions 手動啟動。

- Node.js 22 與 24：核心測試、整段偵測評估及混合區段評估。
- Chromium：載入真正的擴充功能，執行候選、Tab、局部替換與輸入保護整合測試。
- Playwright 版本固定於 `tests/requirements.txt`；瀏覽器依賴依照 [Playwright 官方 CI 說明](https://playwright.dev/python/docs/ci) 安裝。

測試失敗時可在 Actions 查看失敗步驟與日誌。是否要求測試通過才能合併，需另由 repository 的分支規則設定。

## 自動打包與發佈

`scripts/package-release.py` 會從 manifest 收集執行檔案，加上 README 與 McBopomofo／libtabe 授權聲明，建立可重現的 ZIP 及 `SHA256SUMS.txt`。本機可執行：

```sh
python scripts/package-release.py
```

推送版本標籤後，[Release 工作流程](https://github.com/kaiwei6666/typing-recovery/actions/workflows/release.yml) 會確認標籤與 manifest 版本一致，執行核心、偵測及 Chromium 測試，才建立 GitHub Release 並上傳兩個檔案。`v0.*` 或名稱含 alpha／beta／rc 的標籤會標成預覽版；其他版本為正式版。

例如準備 `v0.8.0` 時，先將 `manifest.json` 的版本改為 `0.8.0` 並把所有變更推到 main；確認 Tests 通過後，再建立並推送 `v0.8.0` 標籤。不要重複使用或移動已發佈的標籤。

## 試用回報與混合文字評估

遇到誤報、漏報、替換範圍或候選不正確，請使用 [GitHub 偵測回報表單](https://github.com/kaiwei6666/typing-recovery/issues/new?template=detection-report.md)，附上版本、最小輸入、預期／實際結果與操作方式。Issue 是公開的，請用虛構範例替換私人內容，並保留有影響的空白與大小寫。擴充功能不會自動收集或上傳案例。

```sh
node scripts/evaluate-ranges.cjs
```

`tests/fixtures/range-cases.json` 提供 33 個手工混合文字案例，核對所有區段的 UTF-16 起訖與候選文字；一般核心測試也會驗證替換後周圍內容與游標。評估命令遇到範圍或文字不符會以非零狀態結束。

目前 16 個正常案例未提示，17 個誤打案例中提示 13 個、保守略過 4 個；欄位層級召回率約為 76.5%。這是手工回歸集，不是真實使用者語料；新增案例是回歸規格，不能把案例增加造成的數字變化解讀為模型準確率提升。有提示也不代表每個區段都正確，因此範圍與文字另以精確比對驗證，不能據此宣稱實際準確率。

處理新回報時，先把匿名化且可重現的輸入、意圖與預期範圍加入案例集，再調整規則並執行兩種評估與核心測試。沒有提示但符合目前保守限制的例子，也應保留並註明，不直接放寬門檻。
